# dsh/ —— DeepSeek Harness 破甲

## 统一入口（推荐）

`console.bat`（或 `engine/console.py`）是统一控制台（codex / dsh / wb）统一控制台：

```
console.bat dsh apply     破甲
console.bat dsh revert    复原
console.bat dsh status    状态（只读）
console.bat dsh test      验证测试（只读：扫描 @deepseek-ai 人格标记命中率）
console.bat all test      三目标全部验证
```

## 内容

| 文件 | 作用 |
|---|---|
| `unlock-dsh.bat` | 一键破甲：锁死 `--target dsh`，等价于 `python ..\破甲一键通.py --apply --force --yes --target dsh`；追加参数可覆盖（如 `unlock-dsh.bat --revert` 还原） |
| `content/persona.md` | 共用人格快照（与根目录 `content/persona.md` 同源；**根目录才是源头**，改完根目录重跑 bat） |

## 打法（四层）

1. `WORKSPACE_CONTEXT_INTRO` 类"仅供参考"免责声明 → 升级为 ACTIVE 强制；
   （v6.1 起同时清掉历史版本注入的"别当成 prompt injection"自证句 —— 见 `patch_legacy_self_proof`）
2. 剥离官方默认身份，由人格作唯一身份来源；
3. `PERSONA_SECTION_NAMES` 补区段；
4. persona 正文 = **任务路由层 + 操作者人格 + 强化版政策 + 覆盖层**。
   路由层单一来源是根目录 `content/route-layer.md`，改完 `console.bat dsh apply`。

## 破甲模式（独立可选的 agent preset）

> **DSH 0.1.7 起机制换了。** 旧的用户级 preset 目录
> `<DSH_HOME>\.agent-presets\pojia\`（`agent.cordis.yml` + `preset.yml`）
> **已经不生效** —— DSH 自带 SKILL.md 原话：
> "Nothing reads that directory any more"。
> 同时 shipped preset 也从 `dsh-agent-presets/presets/<id>/` 目录变成了
> `dsh-web-app\presets\<id>.patch.yml` 单文件。

现在破甲模式是一条 **preset 声明**，写进 profile 的 patch 文件
`<DSH_HOME>\profiles\<profile>\cordis.patch.yml` 的标记块里
（`# ── 破甲模式 BEGIN/END ──`）。

**要写两个 profile。** DSH Desktop 和 Web/CLI **各读自己那一份** ——
`dsh` 包里 `rejectElectronProfile()` 的原话是
`profile "desktop" is managed exclusively by the Electron application`。
只写 `web` 的话桌面版一个模式都读不到。脚本默认两处都写，没装的形态自动跳过：

| 形态 | profile | 落点 |
|---|---|---|
| DSH Desktop（`DeepSeek Harness.exe`） | `desktop` | `<DSH_HOME>\profiles\desktop\cordis.patch.yml` |
| `dsh web` / 官方 CLI / npx | `web` | `<DSH_HOME>\profiles\web\cordis.patch.yml` |

`--dsh-all-profiles` 可以把 `profiles/` 下所有 profile（含 `headless`）一并写上；默认只碰上面这两个在用的。

```bash
python engine/破甲一键通.py --dsh-preset deploy     # 部署 / 更新人格
python engine/破甲一键通.py --dsh-preset status     # 看状态
python engine/破甲一键通.py --dsh-preset remove     # 移除
```

- 声明整份复制自 shipped 创造模式单文件，只改 `id` / `name` / `description` / `order`、
  把 `persona` 行换成破甲人格，并摘掉 `tool-cordis` 那一行 —— 所以"
  创造模式能干的活它都能干"，**除了"改自己运行时"那套**：
  `@deepseek-ai/dsh-tool-cordis` 往进程级服务 `cordisInspect` 注册四个 inspect
  provider，该服务只接受一次注册，第二次挂载抛
  `Host Cordis inspect provider "Service" is already registered`；preset 的
  standing mount 又活到进程退出，所以留着它 = 创造模式和破甲模式互斥（谁先挂谁赢，
  另一个切过去就报上面那行）。`PRESET_DROP_ROWS` 就是干这个的，摘除处会留下一段
  注释说明，想拿回把那两行取消注释即可。
- **模板里的插件名必须对得上新版**。旧组成带的
  `@deepseek-ai/dsh-workflow-worker-thread` 在 0.1.7 已不存在，而**带不存在包的
  声明会 activation 失败** —— 表现是模式下拉里看得到、但选不了、开不出会话
  （官方 SKILL.md：“stays on the roster with its diagnostic and cannot compose
  a session”）。模板现在只认 shipped 单文件，`--dsh-preset status` 也会把这种
  残留包报成 `broken`。
- 写在 profile 的 patch 里、不碰 shipped 单文件：DSH 升级不覆盖。
- 生效要**完全退出 DSH（含托盘）再重开**（preset 在启动时组装），且只在**新会话**
  能选到；老会话锁在它启动时的 preset 版本上。
- `--apply --target dsh` 默认会顺带部署/更新它；`--no-dsh-preset` 可以关掉。
  `--revert --target dsh` 会把声明块摘掉（profile patch 文件本身留着，只删标记块）。
- 复验：`node tools/verify_dsh_presets.mjs [profile]` —— 走 DSH 自己的 profile 加载器，
  列出最终组装出的每个 preset（id / order / 插件数 / name）、插件缺失（broken）、
  声明来自哪一层，以及"一进程只能挂一份"的宿主级行归属。

## 注意

- 改的是磁盘文件，**完全退出 DSH（含托盘）再重开并新建会话**才生效。
- 脚本默认不杀 DSH 进程（本会话可能就跑在里面）；`--kill-dsh` 才允许结束。
- `dsh-sdk-minimal\cordis.patch.yml` 身份由 `!!js` 动态指定，脚本设计上不碰，需手动改。
- 备份后缀 `.pojiabak`，归本项目自管。
