# 破甲工作台 · 图形控制台

把 `engine/console.py` 那套命令行操作包成一个 Electron 桌面应用：**部署 / 验证 / 恢复** 三件事，一屏管完。

**七张卡，六个命令行目标** —— Codex / DSH (Web/CLI) / **DSH 桌面版** / WorkBuddy / ZCode / Claude / Hermes。

DSH 拆两张是因为桌面版和 npm 版**共用同一个 `~/.dsh`**（AGENTS.md / skills / 会话都是同一份），
所以提示词状态两边完全一致 —— 两张卡只是让「装没装桌面版」一眼可见。
**执行时折回 dsh**（`bridge.CARD_ONLY`），两张都勾也只跑一遍。

DSH 只有一条提示词通道：`~/.dsh/AGENTS.md` 的标记块。卡片里的下拉决定这次动哪些落点。

## 启动

```bash
# 首次：装运行时（约 100 MB，走 .npmrc 里的国内镜像）
cd gui && npm install

# 启动
npm start
```

或者直接双击 `gui\启动工作台.bat`。
项目根目录的 `破甲工作台.bat` 也能起。

## 界面

界面按浅色工作台风格重构：左侧 236px 导航（品牌块 + 五项 + 版本），右侧为「页头（eyebrow + 大标题 + 操作按钮）+ 内容区」，底部沉底日志与归一预览。卡片是 16px 圆角的白色面板，主色 `#2563eb`，指令页用紫色 `#6d28d9` 做强调。

| 区域 | 作用 |
|---|---|
| 页头 | 每个视图统一的标题区：小标签（DEPLOY TARGETS / PROMPT INJECTION…）、大标题、一句说明；右侧是该视图的主操作按钮 |
| 工具条 | 部署 / 预演 / 验证 / 还原 —— 作用于卡片上勾选的目标。右边的「全选 / 全不选 / 反选」直接改勾选状态，卡片左侧的勾选框与卡片灰态一起跟着变（两处同源，不会一个动一个不动） |
| 席位卡片 | 七个卡片位各一张：状态徽章、落点路径、体检指标；点标题栏的箭头展开逐文件明细 |
| DSH 桌面版卡 | 安装根、`DeepSeek Harness.exe`、提示词与 skills 的状态。**下拉和 DSH 卡完全一样** —— 两版共用同一个 `~/.dsh`，所以两台的勾选也是共享的（勾哪台效果都一样） |
| DSH 卡里的下拉 | `本次动作 ▾` —— 提示词 + skills / 只写提示词 / 只投放 skills / 都不做，见下节 |
| 部署历史 | 点「历史」打开：每次部署 / 恢复的快照列表，每行可**校验**或**回退** |
| 执行日志 | 命令行的实时输出（ANSI 已剥、按级别着色）；可切到 `状态/破甲日志.txt` 末尾 400 行 |
| 归一预览 | 输入用户原话，看会被归到哪个类目；命不中就说明该往 `content/route-layer.md` 补一行 |
| 状态栏 | Python 解释器、项目目录、最近检测时间 |

### 指令提示词页（按 Agent 管理 Markdown）

页面结构自上而下：**Agent 切换条 → 当前 Agent 状态面板 → 分类标签 → 卡片网格**。点卡片只选中，编辑走铅笔图标，进入同页的编辑态（不是弹窗）。

| 区块 | 说明 |
|---|---|
| Agent 切换条 | Codex / Claude / DSH / WorkBuddy / ZCode / Hermes，每项左侧是该客户端的真实图标（从本机安装包里提取，存在 `gui/renderer/icons/`）。切换后同一套布局，内容换成该 Agent 名下的 md |
| 状态面板 | 当前 Agent、Markdown 总数、自定义数、**注入总开关**（拨右 = 全部启用，拨左 = 全部停用；与卡片上的滑块同源）。开关实时生效，部署后重启客户端才应用到会话 |
| 分类标签 | **ChatGPT 页只有四类**：指令文件 / AGENTS.md / config.toml / SKILL.md（就是部署真正会写的那四类，带计数）；其它 Agent 仍是旧分类。没有「全部」这一档，切换 Agent 时默认落在第一个分类 |
| 卡片网格 | 三列圆角卡片，头部 = MD 图标 + 文件名 + 右侧**滑动拖杆**（拨右 = 启用注入，拨左 = 停用）；正文 = 说明（有备注时显示备注）；底部 = 状态徽标 / 体积·分类 + 图标操作（三横线写备注、铅笔编辑、垃圾桶删除）。没有禁用态的开关，生成产物和叶子也能随手拨 |
| 备注 / 新建 | 点三横线写备注、点「新建指令」输入名称：走**页内居中弹窗**（不用系统弹窗），Esc / 点遮罩 / 取消都能关；备注 ≤200 字，留空即清除。备注存在 `状态/_doc_notes.json`（原子写），**不写进源件** |
| 批量条 | 网格顶部：本类份数 / 已停用数 + 「本类启用」「本类停用」。一次桥调用写完，**不弹确认**，卡片状态先翻、失败才回滚 |
| 停用的含义 | 拨左只是把这份从合成清单里摘掉 —— 状态写进 `状态/_doc_inject.json`，**源文件一个字节不动、不改名**（改名会让生成脚本和引擎按固定路径找源件时对不上）。拨回来即恢复 |
| 全部关掉 | 该席位的注入源全关 = **按官方原版处理**：部署时引擎直接走 revert，把实盘撤干净，不留半份旧内容 |
| 编辑态 | 页内表单：大号等宽文本框、**输入后自动保存**（停手约 1 秒落盘，失焦立刻保存），头部只留「复制 / 撤销改动 / 返回」；切到别的文档再回来，未落盘的草稿还在；生成产物顶部有黄色提示条 |

各 Agent 归到哪些文件：

| Agent | 收录范围 |
|---|---|
| codex | **四个落点**：`targets/codex/instructions/*.md`（指令文件候选）→ `~/.codex/prompts/<选中的名字>`；同一份正文写进 `~/.codex/AGENTS.md` 标记块；`~/.codex/config.toml` 的 `model_instructions_file` 指向部署位；`~/.codex/skills/<id>/SKILL.md`（6 父类 + 80 叶子） |
| claude / dsh / workbuddy / zcode / hermes | `content/persona.md`、`content/seats/<agent>.md`、该席位的 `*_md.md` 托管源（claude_md / workbuddy_user_md）+ `targets/<目录>/**/*.md`；dsh / workbuddy 另收席位目录里的 `persona.md`（同名，会合并去重） |

### ChatGPT 的四落点

| 界面分类 | 源件 | 部署到 | 开关含义 |
|---|---|---|---|
| 指令文件 | `targets/codex/instructions/Argon.md`（或 unlock.md …） | `~/.codex/prompts/<文件名>` | 拨右 = 用这一份部署；两份互斥，旧的自动落回未部署。拨左 = 还原 |
| AGENTS.md | **本机 `~/.codex/AGENTS.md` 原文** | 同一份文件的 `<!-- POJIA-CODEX:BEGIN/END -->` 标记块 | 拨左 = 这一路不写（用户原有内容保留） |
| config.toml | **本机 `~/.codex/config.toml` 原文** | 同一份文件的 `model_instructions_file` | 拨左 = 不改指针 |
| SKILL.md | `content/routes/leaves/<id>.md` | `~/.codex/skills/<id>/SKILL.md` | 拨左 = 下次部署撤下这一份。卡片标题是「中文小类名 · id」，标签是 `类目名` · `小类/父类目` · `已投放/未投放`，说明行写明命中关键词 |

实现是 `engine/codex_deploy.py`（plan / deploy / verify / restore 四个动作）。
写入前把原文件快照到 `~/.codex/pojia-backups/<三级路径>.bak`，只存一份、已存在不覆盖；
「还原」先按备份回拷，没有备份才按标记块清理。部署状态记在 `状态/_codex_deploy.json`。

**AGENTS.md 与 config.toml 两张卡点开就是本机原文**（`~/.codex/` 下那两个文件），不是项目里的副本；改完保存直接写回本机，旧内容备份到 `状态/editor-backup/`。

部署目标页的 ChatGPT 卡片读的也是这份 verify 结果：指令文件 / AGENTS.md / config.toml 三路是否就位、86 份 SKILL.md 投了几份。

写回规则：只允许 `content/` 与 `targets/` 下的 `.md`，越界路径直接拒；写前把原内容备份到 `状态/editor-backup/`；`route-layer.md`、`leaves/` 下的文件标为「生成」，改源件后重跑生成脚本，别直接改产物。新建统一落在 `content/seats/custom_<name>.md`。

注入开关：除生成产物外，每份文档都能单独停用 —— 状态写进 `状态/_doc_inject.json`，源件不动；`route-layer.md` 与 `routes/leaves/` 的开关是灰的，要改请改源件重新生成。

快捷键：`F5` 刷新状态，`F9` 验证。下拉的选择记在浏览器本地存储里，重开工作台会记住。

**刷新什么时候真去检测**（一次全量检测要 4 秒上下，所以能省就省）：

| 触发 | 行为 |
|---|---|
| `F5` / 点「刷新」 | **强制全量重探** —— 手动刷新就是「我要看现在的真实状态」 |
| 部署 / 预演 / 恢复收尾 | 只重探**本次动过的目标**（强制的），其余沿用缓存 |
| 验证收尾、切窗口回来 | 走缓存 + 5 秒冷却：20 秒内探过的卡直接复用，不重打一次桥 |
| 恢复历史 / 换 Python 解释器 | 全量强制重探（这两个动作之后，之前的探测结果都不可信） |

冷却窗口内的多次刷新请求会**合并成一次**（5 秒内最多真探一回），卡片也不再整块重建 —— 只就地改徽标、落点和明细，所以刷新时列表不会跳、也不会闪。

## DSH 卡片里的「本次动作」下拉

DSH 有两个落点可以分开动，所以那张卡里多一个下拉 `本次动作 ▾`（落点路径下面那一行）：

| 选项 | 部署 | 恢复 |
|---|---|---|
| **提示词 + skills**（默认） | 写 AGENTS.md 标记块 + 投放路由 skills | 两样都撤 |
| **只写提示词** | 只写 AGENTS.md（等价 `--dsh-agents deploy`） | 只摘标记块，skills 留着 |
| **只投放 skills** | 只投放 skills（等价 `--no-dsh-agents`） | 只撤 skills，AGENTS.md 不动 |
| **都不做** | 本次**跳过 DSH**，别的目标照跑 | 同左 |

按钮上直接回显，点「部署」时实际跑什么也一并列出。恢复的二次确认框里会写清这次动的是哪部分。
菜单是**卡片内联展开**的（卡片本身 `overflow: hidden`，浮层会被裁掉），展开后卡片变高、跟着卡片区一起滚。
再点一次按钮收起。勾选改动只是换个开关，不重新探测（省一次几秒的安装基点扫描）。

### `当前：…` 那行报的是什么

下拉按钮**下面**那一行报的是**盘上现在实际有什么**，跟上面下拉框无关（下拉说的是"这次要做什么"）。每次刷新 / 验证都会重算：

| 状态行 | 灯色 | 含义 |
|---|---|---|
| `当前：已部署 提示词（本版）+ 路由 skills（已投放）` | 绿 | 两样都在，且是本版 |
| `当前：只部署了提示词（本版）· 路由 skills 还没投放` | 黄 | AGENTS.md 有标记块，skills 没投 |
| `当前：只投放了路由 skills · 提示词还没写入` | 黄 | 只有 skills，AGENTS.md 干净 |
| `当前：什么都没部署 —— 提示词与 skills 都没写入` | 灰 | 干净态，什么都没动 |

括号里是提示词那半的版本面值：`本版` / `旧版`。同一句话也会出现在命令行验证里（`python gui/bridge.py test dsh` → `[当前部署] …`）。

### 体检项与明细

- `提示词`：AGENTS.md 标记块的状态 —— 已写入 / 旧版 / 未写入；
- `路由 skills`：我们投了几份（86 份为全量）；
- `预算`：AGENTS.md 的字节数与 65536 上限。**超了会被 DSH 截断**，这一项会标黄，明细里也有提醒。

明细里还能看到两个落点的实际路径与生效方式：
agent-instructions 在**会话首轮**读取 AGENTS.md，已开着的会话不会重读 ——
改完**新建会话**就能生效，不需要重启 DSH。

命令等价物：

```bash
python engine/破甲一键通.py --dsh-agents deploy     # 只写 AGENTS.md 标记块
python engine/破甲一键通.py --dsh-agents remove     # 只摘标记块
python engine/破甲一键通.py --dsh-agents status     # 看状态
```

## 状态徽章

| 徽章 | 含义 |
|---|---|
| 已部署 · 本版 | 部署产物与当前脚本版本一致 |
| 已部署 · 旧版 | 装了，但是旧版文本（需要重新部署） |
| 未部署 | 没装 |
| 未安装 / 异常 | 程序目录都找不到 |
| 部分命中 | 一部分文件是本版、一部分不是 |

## 架构

```
Electron 渲染层 (renderer/)
      ↓ IPC
   main.js            ← 探测 Python、转发调用、流式日志
      ↓ spawn
   bridge.py          ← JSON 桥：把 破甲一键通 的输出转成结构化数据
      ↓ 复用
console.py / 破甲一键通.py   ← 真实操作全在这一层，GUI 不含任何注入逻辑
```

**GUI 不做任何注入逻辑**，只负责调用和展示。改注入内容仍然改 `engine/破甲一键通.py` / `content/persona.md` / `content/route-layer.md`，GUI 会自动反映。

## bridge.py 接口

```bash
python gui/bridge.py meta                      # 版本、路由层体量、persona、事务状态
python gui/bridge.py status codex,dsh,wb       # 目标结构化状态
python gui/bridge.py status pojia              # DSH 提示词落点快照（命令行伪目标，GUI 不请求它）
python gui/bridge.py test   all                # 只读验证（含路由层正/反向校验）
python gui/bridge.py route  "帮我弄个挂"        # 归一预览
python gui/bridge.py tx     list               # 部署历史（事务快照）
python gui/bridge.py tx     verify <编号>       # 快照完整性 + 当前落盘态
python gui/bridge.py tx     restore <编号>      # 按快照回退
python gui/bridge.py run    apply codex,zcode  # 执行，NDJSON 流式输出
python gui/bridge.py run    apply dsh no-agents   # 只投放 skills，不动 AGENTS.md
python gui/bridge.py run    apply dsh no-skills   # 只写 AGENTS.md，skills 不动
python gui/bridge.py run    agents-deploy      # 只部署 AGENTS.md 标记块
python gui/bridge.py run    agents-remove      # 只移除
python gui/bridge.py run    agents-status      # 看状态
```

`pojia` 是**命令行专用伪目标** —— `status pojia` 能看 DSH 提示词落点的快照，但它不会被透传给 `engine/console.py`（那样会变成「未知目标」），也不会被 `all` 展开带上。`run` 的第四个参数是逗号分隔的开关名：`no-agents`（只投放 skills）/ `no-skills`（只写 AGENTS.md）。

渲染层自检（不开 Electron —— 沙箱里起 Electron 会触发 CEF 的 GPU 崩溃风暴）：

```bash
node gui/tools/check_render.mjs     # 函数级：卡片结构 / 回显 / 四个开关的映射（63 项）
node gui/tools/check_boot.mjs       # 端到端：真跑 bind()+boot()，点「部署」看实际发什么给桥（40 项）
node gui/tools/check_contract.mjs   # 三层接口契约：renderer → preload → ipcMain、id、class（14 项）
```

三个脚本分工不同，别互相替代：`check_render` 管"画出来长什么样"，`check_boot` 管"点下去发什么命令"，
`check_contract` 管"三层之间的名字有没有对错"（改名只改一边，就是它兜住的）。

三个一起跑（外加 Python 单测、路由自检、文档与版本一致性）用一条命令，见 `../tools/check_all.py`；
`gui/package.json` 里也挂了 `npm run check`。

单独跑 bridge 也能用，不依赖 Electron。

## 部署历史

每次 `apply` / `revert` 都留一份快照（`状态/tx/`）。回退前会逐文件核对当前内容是否仍等于部署后的状态 —— 被别的程序或人改过就**中止并保留现场**，不硬覆盖。命令行等价物是 `python engine/console.py tx`。

## Python 解释器

按顺序找：`gui/.python-path` 缓存 → `POJIA_PYTHON` 环境变量 → 项目 `.venv`（`Scripts/python.exe`）→ PATH 上的 `python` → WorkBuddy 自带 python（**保底，不是默认**）。

找不到时点右下角的 `python` 手动指定，路径会缓存在 `gui/.python-path`。

## 起不来的话

| 现象 | 处理 |
|---|---|
| 进程一闪就没，日志里有 `GPU process isn't usable` | 加 `--disable-gpu --no-sandbox` 启动（无独显 / 远程桌面 / 沙箱环境常见） |
| `require('electron')` 返回的是个路径字符串 | 环境里有 `ELECTRON_RUN_AS_NODE=1`，启动脚本已 `set "ELECTRON_RUN_AS_NODE="` 清掉 |
| 改了 CSS 但界面没变 | Chromium 缓存了 `file://` 资源，关掉应用重开（不是布局写错） |

## 回退

GUI 是纯前端，删掉 `gui/` 目录即可，不影响命令行用法。
