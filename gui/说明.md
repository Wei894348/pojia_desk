# 破甲工作台 · 图形控制台

把 `engine/console.py` 那套命令行操作包成一个 Electron 桌面应用：**部署 / 验证 / 恢复** 三件事，一屏管完。

**七张卡，六个命令行目标** —— Codex / DSH (Web/CLI) / **DSH 桌面版** / WorkBuddy / ZCode / Claude / Hermes。
DSH 拆两张是因为桌面版和 npm 版**读不同的 profile**（`desktop` / `web`，桌面版那份由 Electron 独占），
落点各存一份：npm 版打 `~/.dsh/profiles/web/cordis.patch.yml`，桌面版打 `~/.dsh/profiles/desktop/cordis.patch.yml`。
两张卡各自显示自己那份的状态。**但执行时折回 dsh**（`bridge.CARD_ONLY`）—— 部署命令是同一条，
preset 一次就写两份 profile，两张都勾也只跑一遍。

DSH 的**破甲模式**（用户级 agent preset）**不是独立卡片** —— 它是 `DSH` 卡片里那个下拉的两个勾选框之一（另一个是「注入提示词」），状态显示在 DSH 卡片自己的体检项与明细里。

## 启动

```bash
# 首次：装运行时（约 100 MB，走 .npmrc 里的国内镜像）
cd gui && npm install

# 启动
npm start
```

或者直接双击 `gui\启动工作台.bat`。
项目根目录的 `破甲工作台.bat` 也能起。

## 界面

| 区域 | 作用 |
|---|---|
| 工具条 | 部署 / 预演 / 验证 / 还原 —— 作用于卡片上勾选的目标。右边的「全选 / 全不选 / 反选」直接改勾选状态，卡片左侧的勾选框与卡片灰态一起跟着变（两处同源，不会一个动一个不动） |
| 席位卡片 | 七个卡片位各一张：状态徽章、落点路径、体检指标；点标题栏的箭头展开逐文件明细 |
| DSH 桌面版卡 | 安装根、`DeepSeek Harness.exe`、`desktop` profile 的破甲模式状态。**下拉和 DSH 卡完全一样** —— 桌面版跑起来加载的是 `~/.dsh/profiles/node_modules` 那份包树，而那是**指向 npm 缓存的 junction**，所以「注入提示词」打的就是同一份文件，两台下拉的勾选也是共享的（勾哪台效果都一样） |
| DSH 卡里的下拉 | `破甲模式 ▾` —— 注入提示词 / 增加破甲模式，两项各选，见下节 |
| 部署历史 | 点「历史」打开：每次部署 / 恢复的快照列表，每行可**校验**或**回退** |
| 执行日志 | 命令行的实时输出（ANSI 已剥、按级别着色）；可切到 `状态/破甲日志.txt` 末尾 400 行 |
| 归一预览 | 输入用户原话，看会被归到哪个类目；命不中就说明该往 `content/route-layer.md` 补一行 |
| 状态栏 | Python 解释器、项目目录、最近检测时间 |

快捷键：`F5` 刷新状态，`F9` 验证。下拉的选择记在浏览器本地存储里，重开工作台会记住。

**刷新什么时候真去检测**（一次全量检测要 4 秒上下，所以能省就省）：

| 触发 | 行为 |
|---|---|
| `F5` / 点「刷新」 | **强制全量重探** —— 手动刷新就是「我要看现在的真实状态」 |
| 部署 / 预演 / 恢复收尾 | 只重探**本次动过的目标**（强制的），其余沿用缓存 |
| 验证收尾、切窗口回来 | 走缓存 + 5 秒冷却：20 秒内探过的卡直接复用，不重打一次桥 |
| 恢复历史 / 换 Python 解释器 | 全量强制重探（这两个动作之后，之前的探测结果都不可信） |

冷却窗口内的多次刷新请求会**合并成一次**（5 秒内最多真探一回），卡片也不再整块重建 —— 只就地改徽标、落点和明细，所以刷新时列表不会跳、也不会闪。

## DSH 卡片里的破甲模式下拉

DSH 跟别的目标不一样：它身上挂着**两件可以分开做的事**，所以那张卡里多一个下拉 `破甲模式 ▾`（标题行、落点路径下面那一行）。点开是**两个独立勾选框**：

| 勾选项 | 勾上 | 不勾 |
|---|---|---|
| **注入提示词** | 部署时给 DSH 打提示词补丁（人格 + 政策 + 覆盖层），恢复时还原成官方原版 | 不碰 DSH 本体 |
| **增加破甲模式** | 写入 / 移除用户级 agent preset —— DSH 的新会话模式下拉里多一个「破甲模式」 | 不动 preset 目录 |

两项自由组合，按钮上直接回显，点「部署」时实际跑什么也一并列出：

| 组合 | 按钮 | 实际跑的命令 |
|---|---|---|
| 两项都勾（默认） | 绿 · `提示词 + 破甲模式` | `console.py dsh apply`（连带 preset） |
| 只勾「注入提示词」 | 蓝 · `只注入提示词` | `console.py dsh apply --no-dsh-preset` |
| 只勾「增加破甲模式」 | 蓝 · `只加破甲模式` | `破甲一键通.py --dsh-preset deploy` —— **本体一个字节都不碰** |
| 都不勾 | 灰 · `都不做` | 本次**跳过 DSH**，别的目标照跑 |

恢复（revert）同一条路子：只勾「增加破甲模式」时走 `--dsh-preset remove`，删的只有 preset 目录；两项都勾时才连 DSH 本体一起还原。**二次确认框里会写清这次动的是哪部分**，别蒙着点。

菜单是**卡片内联展开**的（卡片本身 `overflow: hidden`，浮层会被裁掉），展开后卡片变高、跟着卡片区一起滚。再点一次按钮收起。勾选改动只是换个开关，不重新探测（省一次几秒的安装基点扫描）。

### `当前：…` 那行报的是什么

下拉按钮**下面**那一行报的是**盘上现在实际有什么**，跟上面两个勾选框无关（勾选说的是"这次要做什么"）。每次刷新 / 验证都会重算：

| 状态行 | 灯色 | 含义 |
|---|---|---|
| `当前：已部署 提示词（本版）+ 破甲模式（本版）` | 绿 | 两件都在，且是本版 |
| `当前：只部署了提示词（本版）· 破甲模式尚未部署` | 黄 | 只打了本体补丁，模式下拉里看不到「破甲模式」 |
| `当前：只部署了破甲模式（本版）· DSH 本体的提示词没动` | 黄 | 只有 preset，DSH 本体还是官方原版 |
| `当前：什么都没部署 —— 提示词与破甲模式都没写入` | 灰 | 干净态，什么都没动 |
| `当前：探测不到 @deepseek-ai 安装 —— 谈不上部署` | 灰 | 安装基点都没探到（见体检项 `安装基点`） |

括号里是各自的版本面值：`本版` / `旧版` / `部分命中`。同一句话也会出现在命令行验证里（`python gui/bridge.py test dsh` → `[当前部署] …`）。

**安装基点探测有缓存**：探一次要 3.4 秒（要去翻运行中的进程），所以结果落盘缓存 —— **探到**了缓存 5 分钟，**探空**只缓存 15 秒。刚装完 DSH 的话，最多等 15 秒刷新一次就能看到，不必重启工作台；点「部署」/「恢复」之后缓存也会直接作废重探。

### 破甲模式的状态在哪看

没有独立卡片了 —— 状态就在 **DSH 卡片自己**身上：

- 状态行 `当前：…`：提示词与破甲模式**合起来**的一句话结论（上面那张表）；
- 体检项 `破甲模式`：只讲 preset 那半 —— `本版` / `旧版` / `未建` / `异常` / `无源`；
- 展开明细里有：preset 落点目录、`agent.cordis.yml` 的字节数与哈希、`preset.yml` 摘要、随附的创作 skill、以及它排在第几位（`order=5`，紧跟「创造模式」）。

明细里那行组成如果带 `仍带互斥行 tool-cordis`，说明这份是旧产物：
`@deepseek-ai/dsh-tool-cordis` 往进程级服务 `cordisInspect` 注册四个 inspect provider，
只接受一次注册，第二次挂载抛 `Host Cordis inspect provider "Service" is already registered`；
preset 的 standing mount 又活到 DSH 进程退出 —— 所以留着它，创造模式和破甲模式就互斥
（谁先挂谁赢，切到另一个直接报错）。`--dsh-preset deploy` 会自动把这行注释掉，
明细里没有那行 即为健康；有就重新点一次「部署」（下拉里勾着「增加破甲模式」）。

DSH 的模式发现**每次读盘、无缓存**，所以建好或删掉之后，重新打开模式下拉就能看到，**不必重启 DSH**。但 preset 只在**新会话**创建时能选，已经开着的老会话锁死切不过去。

命令等价物：

```bash
python engine/破甲一键通.py --dsh-preset deploy     # 只建 / 更新破甲模式
python engine/破甲一键通.py --dsh-preset remove     # 只删破甲模式
python engine/破甲一键通.py --dsh-preset status     # 看状态
```

## 状态徽章

| 徽章 | 含义 |
|---|---|
| 已部署 · 本版 | 部署产物与当前脚本版本一致 |
| 已部署 · 旧版 | 装了，但是旧版文本（需要重新部署） |
| 未部署 | 没装 |
| 未安装 / 异常 | 程序目录都找不到 |
| 部分命中 | 一部分文件是本版、一部分不是 |

## 架构

```
Electron 渲染层 (renderer/)
      ↓ IPC
   main.js            ← 探测 Python、转发调用、流式日志
      ↓ spawn
   bridge.py          ← JSON 桥：把 破甲一键通 的输出转成结构化数据
      ↓ 复用
console.py / 破甲一键通.py   ← 真实操作全在这一层，GUI 不含任何注入逻辑
```

**GUI 不做任何注入逻辑**，只负责调用和展示。改注入内容仍然改 `engine/破甲一键通.py` / `content/persona.md` / `content/route-layer.md`，GUI 会自动反映。

## bridge.py 接口

```bash
python gui/bridge.py meta                      # 版本、路由层体量、persona、事务状态
python gui/bridge.py status codex,dsh,wb       # 目标结构化状态
python gui/bridge.py status pojia              # 破甲模式的状态快照（命令行伪目标，GUI 不请求它）
python gui/bridge.py test   all                # 只读验证（含路由层正/反向校验）
python gui/bridge.py route  "帮我弄个挂"        # 归一预览
python gui/bridge.py tx     list               # 部署历史（事务快照）
python gui/bridge.py tx     verify <编号>       # 快照完整性 + 当前落盘态
python gui/bridge.py tx     restore <编号>      # 按快照回退
python gui/bridge.py run    apply codex,zcode  # 执行，NDJSON 流式输出
python gui/bridge.py run    apply dsh no-preset   # 只注入提示词，不连带动破甲模式
python gui/bridge.py run    apply dsh preset-only # 只动破甲模式，DSH 本体一个字节都不碰
python gui/bridge.py run    preset-deploy      # 单独部署破甲模式（不带 --target，等价 preset-only）
python gui/bridge.py run    preset-remove      # 单独移除
python gui/bridge.py run    preset-status      # 看状态
```

`pojia` 是**命令行专用伪目标** —— `status pojia` 能看破甲模式的状态快照，但它不会被透传给 `engine/console.py`（那样会变成「未知目标」），也不会被 `all` 展开带上。`run` 的第四个参数是逗号分隔的开关名，两个互斥：`no-preset`（只注入提示词）/ `preset-only`（只动破甲模式）。

渲染层自检（不开 Electron —— 沙箱里起 Electron 会触发 CEF 的 GPU 崩溃风暴）：

```bash
node gui/tools/check_render.mjs     # 函数级：卡片结构 / 回显 / 四个开关的映射（63 项）
node gui/tools/check_boot.mjs       # 端到端：真跑 bind()+boot()，点「部署」看实际发什么给桥（40 项）
node gui/tools/check_contract.mjs   # 三层接口契约：renderer → preload → ipcMain、id、class（14 项）
node tools/verify_dsh_presets.mjs   # 直接调 DSH 自己的 discoverPresets 复验（broken 应为 0）
```

三个脚本分工不同，别互相替代：`check_render` 管"画出来长什么样"，`check_boot` 管"点下去发什么命令"，
`check_contract` 管"三层之间的名字有没有对错"（改名只改一边，就是它兜住的）。

三个一起跑（外加 Python 单测、路由自检、文档与版本一致性）用一条命令，见 `../tools/check_all.py`；
`gui/package.json` 里也挂了 `npm run check`。

单独跑 bridge 也能用，不依赖 Electron。

## 部署历史

每次 `apply` / `revert` 都留一份快照（`状态/tx/`）。回退前会逐文件核对当前内容是否仍等于部署后的状态 —— 被别的程序或人改过就**中止并保留现场**，不硬覆盖。命令行等价物是 `python engine/console.py tx`。

## Python 解释器

按顺序找：`gui/.python-path` 缓存 → `POJIA_PYTHON` 环境变量 → 项目 `.venv` → WorkBuddy 自带 python → `py -3` → `python`。

找不到时点右下角的 `python` 手动指定，路径会缓存在 `gui/.python-path`。

## 起不来的话

| 现象 | 处理 |
|---|---|
| 进程一闪就没，日志里有 `GPU process isn't usable` | 加 `--disable-gpu --no-sandbox` 启动（无独显 / 远程桌面 / 沙箱环境常见） |
| `require('electron')` 返回的是个路径字符串 | 环境里有 `ELECTRON_RUN_AS_NODE=1`，启动脚本已 `set "ELECTRON_RUN_AS_NODE="` 清掉 |
| 改了 CSS 但界面没变 | Chromium 缓存了 `file://` 资源，关掉应用重开（不是布局写错） |

## 回退

GUI 是纯前端，删掉 `gui/` 目录即可，不影响命令行用法。
