# codex/ —— Codex CLI 破甲

## 统一入口（推荐）

根目录 `console.bat` / `console.py` 是三目标（codex / dsh / wb）统一控制台：

```
console.bat codex apply     破甲
console.bat codex revert    复原
console.bat codex status    状态（只读）
console.bat codex test      验证测试（只读：核对关键段+新鲜度）
console.bat all test        三目标全部验证
```

## 内容

| 文件 | 作用 |
|---|---|
| `unlock-codex.bat` | 一键破甲：锁死 `--target codex`，等价于 `python ..\破甲一键通.py --apply --force --yes --target codex`；追加参数可覆盖（如 `unlock-codex.bat --revert` 还原） |
| `codex_apply.py` | Python 驱动：`--status` 只查状态 / `--revert` 还原 / 默认 apply --force（已内置 schtasks 打桩，可在受限环境跑） |
| `codex-unlock-instructions.md` | 当前部署到 `C:\Users\86157\.codex\` 的指令文件**快照**（约 40 KB，含任务路由层）。**由 `--apply` 自动同步**，内容一致时不写盘 |

## 生效链路

`C:\Users\86157\.codex\config.toml` 顶层 `model_instructions_file = "./codex-unlock-instructions.md"`
→ 新会话加载该 Markdown（五层：身份授权头 → **任务路由层** → 反拒绝铁律 → 创作许可前提 / 操作者人格 / 内容政策 / 覆盖声明 → Codex 工作方式 + 最终覆盖 + 发送前自检）。

## 注意

- **只对新会话生效**；运行中的旧会话不会重新读取。
- Codex 桌面端退出时可能回写 config.toml，部署后如异常先看该文件顶部部署块是否还在。
- 还原：`unlock-codex.bat --revert`。
- 指令文件由脚本生成，**不要直接手改**快照或部署文件——改根目录 `persona.md` 后重跑 bat。
- 那份项目快照（本目录里的 `codex-unlock-instructions.md`）由 `--apply` 自动同步，
  三条出口都会补：已是最新跳过 / 无变化跳过 / 真写完。它记的是**本脚本这一版**
  生成了什么 —— 实盘若是别版人格（旧版本打的补丁），快照**故意不跟着变**。
  漂移判据：`tests/test_codex_snapshot.py` 里最后一项会逐字节比对快照与实盘。
